# AIEnglish MVP 交付与当前状态说明

> 更新时间：2026-08-19
> 当前版本：0.1.0
> 交付状态：可运行的局域网体验版 MVP
> 产品与 UI 基线：[AI_ENGLISH_APP_PRODUCT_UI_PLAN.md](./AI_ENGLISH_APP_PRODUCT_UI_PLAN.md)

## 1. 交付结论

AIEnglish 已从产品与视觉方案进入可交互 MVP 阶段。当前系统具备本地登录、五篇种子内容、每日六步学习流程、档案馆编辑风格 UI、学习记录、跳过文章、一键启动和关闭，以及同一 Wi-Fi 下的手机访问能力。

当前版本适合个人试用、学习流程验证和后续功能迭代，尚不适合公开互联网部署或多人正式使用。1000 篇内容目标、真实 AI 批改、跨设备数据同步、HTTPS 和生产级数据存储仍属于后续建设范围。

## 2. 任务目标

### 2.1 产品目标

- 每天提供一篇约 150 词的精选英语材料。
- 用连续长对话承载完整学习过程，减少页面切换。
- 覆盖导读、听力、翻译、口语、写作和总结六个环节。
- 通过难度分级、来源记录、质量评分和学习档案形成可持续内容体系。
- 同时适配电脑、平板和手机，支持个人日常使用。

### 2.2 本轮 MVP 目标

- 按已确认方案实现“档案馆编辑风格”界面。
- 将六步进度放在“今日学习”标题下方。
- 使用本地账号登录，密码不以明文写入代码或仓库。
- 先完成内容采集与校验流水线，录入 5 篇质量合格的种子内容。
- 支持跳过当前文章并继续下一篇。
- 提供 Windows 一键启动和一键关闭能力。
- 支持手机在同一局域网中访问。

### 2.3 中长期目标

- 内容库从 5 篇扩充到 1000 篇，并按 L1、L2、L3 分级。
- 将当前模拟评分替换为真实的 TTS、语音识别、口语评分、翻译和写作批改。
- 将浏览器本地进度升级为可跨设备同步的服务端数据。
- 建立可持续运行的内容采集、清洗、去重、拆分、审核和发布流程。

## 4. 已完成内容

### 4.1 产品、视觉与响应式界面

- 已形成完整的产品、内容和 UI 方案。
- 已完成三轮视觉方向探索并选定档案馆编辑风格。
- 已实现响应式应用外壳，覆盖电脑、平板和手机布局。
- 已实现登录页、今日学习、对话档案、复盘和个人档案四个主要界面。
- 六步学习进度已放在“今日学习”下方，并支持点击定位到对应学习环节。
- 今日学习内容使用连续展开的对话流，保留完成、进行中和未开始状态。

### 4.2 每日学习流程

- 导读：展示文章学习目标和核心问题。
- 听力：使用浏览器语音合成朗读，支持 `0.75×`、`1×`、`1.25×` 速度及原文展开。
- 翻译：支持输入、提交、模拟评分、参考译文和评分提示。
- 口语：支持浏览器麦克风录音、回听和模拟评分；无麦克风权限时可进入练习模式。
- 写作：支持两次作答机会、提示、参考表达和答案判定。
- 总结：生成翻译、口语、写作综合分与当日掌握内容。
- 支持跳过当前文章，并自动切换到下一篇未跳过内容。
- 支持查看五篇内容的未开始、进行中、已完成和已跳过状态。

### 4.3 登录与服务端

- 已实现登录、会话查询、退出登录和健康检查 API。
- 用户名和密码散列由 `.env.local` 提供，密码使用 `scrypt` 验证。
- 会话令牌通过 `HttpOnly`、`SameSite=Lax` Cookie 保存。
- 服务支持开发模式和构建后静态资源托管。
- 服务现监听 `0.0.0.0`，可从本机和局域网设备访问。

### 4.4 内容库与采集校验流水线

- 已入库 5 篇种子内容，目标规模为 1000 篇。
- 当前来源为 CDC、EPA、NOAA、NASA 和 NIST。
- 每篇内容包含：中英文标题、主题、难度、正文、导读、核心观点、翻译题、口语题、写作题、词汇、来源和质量评分。
- 已实现内容结构校验、HTTPS 来源校验、来源 URL 去重、正文指纹去重、最低质量分检查和题目完整性检查。

### 4.5 学习数据

- 页面刷新后可以恢复同一浏览器中的学习进度。

### 4.6 工程化与运行脚本

- 已建立 React 19、TypeScript 7、Vite 8 和 Node.js 服务端工程。

- 一键启动脚本支持依赖检查、重复启动检测、健康检查、后台运行、PID 和日志记录。
- 一键启动脚本会自动识别并显示可供手机访问的局域网地址。
- 一键关闭脚本只关闭由启动脚本记录的 Node.js 进程，避免误关其他程序。

## 6. 当前问题与风险

### P0：影响产品核心目标

1. **内容规模仅完成 5/1000。** 当前完成度为 0.5%，只适合验证数据结构和学习流程。
2. **批改与评分仍是模拟逻辑。** 翻译按文本长度生成分数，口语使用固定模拟分，写作主要采用标准化后的精确答案匹配，不能代表真实语言能力。
3. **内容流水线还不是自动采集系统。** 当前脚本负责现有内容的结构、质量、去重和来源可访问性校验，尚未完成批量抓取、正文抽取、长文拆分、自动出题与人工审核工作台。

### P1：影响连续使用与多端体验

1. **学习进度只保存在当前浏览器。** 电脑和手机之间不会同步，清除浏览器数据会丢失记录。
2. **会话只保存在服务内存。** 重启服务后需要重新登录，不支持会话持久化和多实例部署。
3. **手机通过局域网 HTTP 访问。** 登录数据在可信局域网内传输但没有 TLS；部分手机浏览器会禁止非安全来源使用麦克风，因此口语录音可能退化为练习模式。
4. **电脑局域网 IP 可能变化。** 当前手机地址依赖 DHCP 分配，尚无固定域名、mDNS 地址或二维码入口。
5. **尚未建立数据库。** 用户、内容、学习记录和评分结果都没有服务端持久化。

### P2：发布质量与运营风险

1. **当前一键启动运行开发服务器。** 可用于本地体验，但不等同于生产部署方式。
2. **Windows 现有 Node.js 防火墙规则范围较宽。** 后续应改成仅允许专用网络和端口 `4173` 的项目专用规则。
3. **自动化测试不足。** 尚无单元测试、API 集成测试、端到端回归和移动端视觉基线。
4. **内容公开发布边界未建立。** 当前按个人使用场景建设，未形成面向公开发布或商业使用的来源授权、审核和下架流程。
5. **真实 TTS、录音文件和隐私策略未完成。** 当前录音只在浏览器内形成临时对象 URL，没有上传与存储，但未来接入云端能力前需要补齐数据生命周期规则。

- [x] 将局域网配置、当前 IP 检测和手机访问提示集成到启动脚本。

验收标准：新环境按文档安装依赖后可启动，核心流程自动测试通过，仓库工作区干净。

### 阶段 B：把内容流水线从 5 篇扩到可批量生产

目标：先形成稳定的 50 篇样本，再逐步扩到 200 篇和 1000 篇。

- 建立来源白名单、主题配额、难度配额和时间范围规则。
- 实现抓取、正文抽取、清洗、指纹去重和长文连续拆分。
- 引入 CEFR、词频、句长和从句复杂度等难度特征。
- 自动生成导读、词汇、翻译、口语和写作任务，再进入人工抽检。
- 为每篇内容保存原始快照、转换记录、失败原因和版本历史。
- 分批验收：50 篇验证质量标准，200 篇验证流水线吞吐，1000 篇完成首期库。

验收标准：每篇内容可追溯、可重复生成、无重复正文、质量分达标，抽检通过率达到约定阈值。

### 阶段 C：接入真实 AI 学习能力

目标：替换当前模拟评分，让反馈与学习表现真实相关。

- 接入稳定 TTS，补齐进度、暂停、重复和句子定位。
- 接入语音识别，保存转写结果而不是直接使用固定口语分。
- 建立口语评分维度：准确度、流利度、发音、完整度和反馈证据。
- 接入翻译与写作批改，输出错误位置、原因、修改建议和参考表达。
- 建立评分提示词、模型版本、重试和成本记录。

验收标准：同一输入的评分波动可控，反馈可解释，低分重试和异常降级可用。

### 阶段 D：服务端数据与跨设备同步

目标：让电脑和手机共享同一学习档案。

- 引入数据库并迁移用户、课程、学习记录、作答、评分和错题数据。
- 持久化会话，增加登录限速、审计日志和密码重置方式。
- 设计草稿自动保存、冲突处理和离线重试。
- 将对话档案、复盘和个人统计改为服务端真实数据。

验收标准：电脑开始后可在手机继续，服务重启不丢会话和学习记录。

### 阶段 E：手机与发布质量

目标：达到稳定的日常个人使用体验。

- 增加 HTTPS 或可信局域网证书，解决手机麦克风安全上下文限制。
- 增加 PWA 安装、离线壳、弱网提示和更新策略。
- 完成主流手机、平板和桌面浏览器的兼容测试。
- 建立性能、无障碍、隐私、备份和恢复检查。
- 将开发启动和生产运行分开，形成正式部署脚本。

验收标准：真机完整六步流程通过，弱网和重启后可恢复，核心页面无阻断性兼容问题。
